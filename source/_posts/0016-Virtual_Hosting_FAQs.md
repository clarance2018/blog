我第一个网站是用的虚拟主机。那时候什么都不懂，在淘宝上花了几十块钱买了一年——送一个 FTP 账号、一个控制面板、一个"不限流量"的承诺（当然是不限的，因为根本没什么人访问）。

后来我的网站流量上涨了，虚拟主机开始频繁报错——"503 Service Unavailable"。客服说是"资源超限"，解决方案是"升级套餐"。

那时候我意识到一个道理：**没有"不限流量"的套餐，只有"你还没到那个量"的套餐。**

**一句话理解：** 虚拟主机是"合租公寓"，VPS 是"整租房子"，Docker 是"宜家家具"——越往后自由度越高，但需要的能力也越多。

## 各种方案的对比

| 方案 | 成本 | 管理难度 | 性能 | 灵活性 | 推荐场景 |
|------|:----:|:--------:|:----:|:------:|---------|
| 虚拟主机 | 低 | 极低 | 低 | 极低 | 个人博客、简单企业站 |
| VPS/云服务器 | 中 | 中 | 高 | 高 | 中型网站、API 服务 |
| Docker 容器 | 中 | 中高 | 高 | 极高 | 微服务、多应用 |
| Serverless | 按量付费 | 低 | 中 | 中 | 函数计算、API |
| 静态托管 | 极低/免费 | 极低 | 高 | 低 | 博客、文档站（本博客就是） |

### 虚拟主机：入门级选择

虚拟主机的本质是一台服务器被分割成多个"虚拟空间"，每个用户分到一部分资源。

优点：
- **便宜**：几十到几百一年
- **省心**：服务器环境已经配好，上传文件就能用
- **有技术支持**：出问题找客服

缺点：
- **资源受限**：CPU/内存/连接数都有限制
- **不能自由配置**：不能装软件、不能改 PHP 版本
- **安全性差**：同服务器上其他网站有问题可能影响你

### VPS/云服务器：进阶级选择

VPS（Virtual Private Server）通过虚拟化技术给你一台"独立"的服务器。

```bash
# 登录 VPS 后的第一件事
ssh root@your-server-ip

# 更新系统
apt update && apt upgrade -y

# 安装 Nginx
apt install nginx -y

# 配置防火墙
ufw allow 22
ufw allow 80
ufw allow 443
ufw enable
```

VPS 给你的自由度是虚拟主机无法比拟的——你可以自己装任何软件、调任何配置。

> **经验之谈：** 从虚拟主机迁移到 VPS 之后，我干的第一件事就是配了一台 Nginx + Let's Encrypt 的全 HTTPS 站点。那种"我的地盘我做主"的感觉，大概就是技术的快乐所在吧。

### Docker：现代部署方案

Docker 把应用和它的依赖打包成一个"容器"，在任何服务器上都能跑：

```yaml
# docker-compose.yml
version: '3'
services:
  blog:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./public:/usr/share/nginx/html
      - ./nginx.conf:/etc/nginx/conf.d/default.conf
    restart: always
  
  db:
    image: postgres:16-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
```

Docker 最大的好处：**环境一致性。** 你的笔记本上跑的样子，就是服务器上跑的样子——再也不会出现"我本地好好的，怎么部署上去就挂了"这种问题。

## 2026 年的部署方案推荐

根据不同的需求，我建议如下：

| 你的情况 | 推荐方案 | 预算参考 |
|---------|---------|---------|
| 刚入门，只想搭个个人站 | 静态托管（Vercel/Netlify/GitHub Pages） | 免费 |
| 需要一个动态站点（博客、CMS） | 低配 VPS + Nginx + Docker | ¥50-100/月 |
| 企业官网/展示型网站 | 云服务器 + CDN | ¥100-500/月 |
| 高并发应用 | 云服务器集群 + 负载均衡 + 容器化 | ¥1000+/月 |

我自己现在用的是：**Hexo（静态站点生成）→ 构建后 rsync 到 Nginx 服务器 → Cloudflare CDN**。

这个方案的好处是：
1. 静态站点几乎不需要服务器性能，低配 VPS 足够
2. CDN 让全球访问都快
3. 安全性好——没有动态语言的攻击面

## 几个常见的概念（给从虚拟主机入门的同学）

- **FTP**：早期上传文件的协议，2026 年建议用 rsync 或 SFTP 替代
- **域名解析（DNS）**：把域名指向你的服务器 IP，通常在域名管理后台配
- **绑定域名**：在服务器上配置 Nginx 虚拟主机，让特定域名指向特定文件夹
- **默认首页**：访问目录时自动展示的文件，通常是 `index.html` 或 `index.php`
- **MX 记录**：让你的域名可以做邮箱 — 想拥有 `you@yourdomain.com` 就需要配这个

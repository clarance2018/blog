最早建站的时候，有一个网站让我印象特别深——一篇文章介绍了一堆"免费开源建站程序"：WordPress、Discuz、PHPWind、ECShop、DeDeCMS……

十年过去，大部分已经消失在历史长河里了（有的因为安全漏洞太多，有的因为停止维护）。

**一句话理解：** 2026 年建站的选择比十年前多得多——关键不是"哪个免费"，而是"哪个适合你的需求"。

## 2026 年的建站方案分类

### 静态站点生成器（SSG）——个人网站和博客首选

静态站点生成器是 2026 年个人建站的主流方案。它把 Markdown 内容编译成 HTML 文件，部署非常简单。

| 工具 | 语言 | 特点 | 适合 |
|------|------|------|------|
| **Hexo** | Node.js | 速度快、主题丰富 | **博客首选**（本站在用） |
| Hugo | Go | 极快构建速度 | 任何静态站 |
| 11ty | Node.js | 灵活、零配置 | 技术博客 |
| Next.js | React | 全栈能力 | 商业网站 |

静态站的好处：
- **速度快**：纯 HTML，不需要数据库
- **安全**：没有动态语言攻击面
- **便宜**：可以托管在 Vercel、Netlify、GitHub Pages，甚至免费
- **版本可控**：所有内容在 Git 里

> **经验之谈：** 我的博客从 WordPress 迁到 Hexo 之后，加载速度从 3 秒降到了 0.8 秒，而且再也没担心过安全问题。**静态站对于个人博客来说，是性价比最高的方案。**

### 传统 CMS——企业网站和内容型网站

如果你的网站需要非技术人员管理内容，传统的 CMS 仍然是最合适的选择：

| 平台 | 技术 | 适用场景 |
|------|------|---------|
| **WordPress** | PHP | 全能型，插件丰富 |
| **Ghost** | Node.js | 专注于内容出版 |
| **Strapi** | Node.js | 无头 CMS，可自定义 API |
| **Sanity** | SaaS | 云端无头 CMS，团队协作 |

### 无头 CMS + 前端框架（现代企业方案）

"无头 CMS"是指只提供内容管理的后端，不捆绑前端展示。你可以用 React/Vue 做前端，通过 API 获取内容。

```
Headless CMS 工作流：
内容创作者 → Sanity/Strapi（管理内容） → API → React/Vue（前端展示） → 用户
```

这种方案的好处是前端和后端解耦，可以各自独立部署和扩展。

### 建站平台（零代码方案）

如果你完全不想写代码：

| 平台 | 特点 | 适合 |
|------|------|------|
| **Vercel** + 模板 | 一键部署，自动 HTTPS | 开发者的快速启动 |
| **Webflow** | 可视化设计，能导出代码 | 设计师建站 |
| **Framer** | 设计即网站 | 个人 landing page |
| **Squarespace** | 模板丰富，全托管 | 小企业官网 |

## 从建站到部署的完整流程

以我自己的博客（Hexo）为例：

```bash
# 1. 初始化
npx hexo init my-blog
cd my-blog
npm install

# 2. 写文章
npx hexo new post "文章标题"

# 3. 本地预览
npx hexo server

# 4. 生成静态文件
npx hexo generate

# 5. 部署到服务器
rsync -avz public/ user@server:/var/www/html/
```

整个过程从写文章到部署上线，只需要几分钟。关于部署方案的更多选择，可以参考[虚拟主机到 Docker——部署方案](/archives/16/)。

## 不要选"即将过时"的平台

2026 年我不推荐的新建站方案：
- ❌ DeDeCMS（安全漏洞多年未修复）
- ❌ 帝国CMS（已停止维护）
- ❌ PHPWind（Discuz 合并后已停更）
- ❌ 纯 FTP 手动上传（但不妨碍新手用它学习）
